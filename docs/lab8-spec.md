# ЛР8 — циклический код Хэмминга (форма Form10)

Источники: `reference/chm/project8_1/8_1.htm` (теория, рис. 8.1–8.4),
`project8_2/8_2.htm` (подготовка: (7,4), g(x) = x³+x+1, одноканальный и
трёхканальный кодер), `project8_3/8_3.htm` (порядок выполнения),
`reference/lab8_questions.txt`, `reference/forms_all.txt` (блок Form10),
`forms.json` (DFM), декомпиляция `reference/re/dec` + `objdump` по
таблице published-методов `Project1.exe`.

Формулы справки — картинки `8_1.files/imageNNN.wmz` (gzip-WMF); текст извлечён
из `8_1.htm` (cp1251), обозначения сверены по формам DFM (надстрочные цифры —
отдельные `TLabel` с `Caption='2'`, `'3'` и т.д.).

```
s(t+1) = Mᵀ·s(t) + b(t)·e          — состояние фильтра, e = (1,0,…,0)ᵀ
G(x) = 1 + G₁x + G₂x² + … + G_r x^r,    g(x) | x^n + 1,   g(0) = 1
R(x) = [A(x)·x^(n−k)] mod G(x)            — контрольные разряды
A(x) = [A(x)·x^(n−k) + R(x)]              — систематическое кодирование
приём: [A_i(x)·x^(n−k) + R_i(x)] = 0 mod G(x)   — код принят правильно
S(x) = A″(x) mod g(x)                     — синдром, зависит только от ошибки
e(x) = x^p  ⇒  S(x) = x^p mod g(x)        — одиночная ошибка в разряде p
S_t(x) = x^t·S(x) mod g(x)                — автономный режим, период n
```

## Что считается

### Параметры

```
n = 2^r − 1,  k = n − r,  r = deg g,  d_min = 3
pad = (−k) mod v            — фиктивные ведущие нули при v каналах
порог мажоритария = ⌊v/2⌋ + 1  (v = 1…5 → 1, 2, 2, 3, 3)
```

Коды и многочлены (маски — как в форме):

| Код | g(x) | маска | r | k |
|---|---|---|---|---|
| (3,1) | x²+x+1 | 111 | 2 | 1 |
| (7,4) | x³+x+1 | 1011 | 3 | 4 |
| (7,4) | x³+x²+1 | 1101 | 3 | 4 |
| (15,11) | x⁴+x+1 | 10011 | 4 | 11 |
| (15,11) | x⁴+x³+1 | 11001 | 4 | 11 |
| (31,26) | x⁵+x²+1 | 100101 | 5 | 26 |
| (31,26) | x⁵+x³+1 | 101001 | 5 | 26 |

Все семь g(x) делят x^n+1 без остатка, g(0) = 1, период равен n (g не делит
x^d+1 при d < n) — проверено в `check_lab8.py`.

### Схема регистра сдвига (фильтр деления на g(x))

```
           ┌────┬────┬────┐
 вход ──⊕──▶ T1 │ T2 │ …  │ Tr ├──▶ (в линию при 2-м положении ключа)
        ▲   └────┴────┴────┘
        │     ▲     ▲      ▲
        └─────┴─────┴──────┘   отводы там, где G_i = 1 (i = 0…r−1)
```

Состояние — r-разрядный остаток префикса: `s ← (s·x + b) mod g(x)`, где b —
очередной входной разряд (старший первым). После n тактов s = A″(x) mod g(x).
Кодер: такты 1…k — информационные разряды идут в линию и в фильтр; такты k+1…n —
ключ во 2-м положении, обратная связь разомкнута, контрольные разряды
выдвигаются, фильтр обнуляется. Декодер: те же n тактов заполняют буфер,
затем автономные такты (вход 0) дают `S_t = x^t·S mod g`; схема совпадения
узнаёт вычет разряда и инвертирует его.

### Синдромы одиночных ошибок, (7,4), g = 1011

| разряд p (1 — младший) | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| S = x^(p−1) mod g | 001 | 010 | 100 | 011 | 110 | 111 | 101 |

Все 7 ненулевых синдромов заняты — код совершенный, поэтому двойная ошибка даёт
синдром одного из разрядов и «исправляется» в другое кодовое слово. Порт это
показывает: вердикт «Синдром указывает на разряд N, но исправленная комбинация
не совпадает с переданной».

### Пороги мажоритарного декодера

Для v каналов логическая схема имеет v выходов; разряд p обслуживает канал
`p mod v` на такте `p div v` (нумерация с 0). Порог каждого выхода — вычет
`x^p mod g`, то есть ровно строка таблицы синдромов. Порог мажоритарного
элемента — ⌊v/2⌋+1 совпадений.

Справка (8_1.htm, конец раздела): «пусть n = …, k = …, тогда … логическая схема
будет представлять собой две схемы совпадения на следующие коды: … то есть
0 1 1; … то есть 1 0 0». Для (7,4) и v = 2 порт даёт:

| канал | такт | разряд | порог |
|---|---|---|---|
| 1 | 1 | 2 | 100 |
| 2 | 1 | 3 | 011 |

то есть те же коды `1 0 0` и `0 1 1` (порядок каналов обратный — в справке
сначала младший разряд второй группы).

## Численные примеры

### (7,4), g = 1011

```
A = 0111  →  A·x³ = 0111000,  0111000 mod 1011 = 010  →  слово 0111010
A = 1001  →  R = 110,  слово 1001110
A = 0001  →  R = 011,  слово 0001011  (= g(x) со сдвигом)
A = 1011  →  R = 000,  слово 1011000  (A(x) кратен g(x))
```

Приём слова 0111010 с ошибкой в 7-м разряде: принято 1111010, синдром 101 = 5,
исправление разряда 7 даёт 0111010, остаток 0.

### (15,11), g = 10011

```
A = 10110010001  →  R = 1110,  слово 101100100011110
```

### (31,26), g = 100101

```
A = 1011  →  R = 00010,  слово 1011 00010 (26 + 5 = 31 разряд)
```

## Расхождения и адаптации

* **Фиктивные нули.** Справка: при v каналах информационный полином умножают на
  x^pad, чтобы k было кратно v; для (3,1) и v = 2 в форме остаток первого
  канала принудительно обнуляется (`DAT_00529d44 = 0`). В порте pad — ведущие
  нули, которые прогоняются через фильтр до информационных разрядов: остаток
  они не меняют (проверено), длина слова остаётся n, а в таблице тактов
  появляются строки «фикт.». Так сохраняется d_min = 3 для всех v (иначе слово
  длины n+pad теряет корректирующую способность).
* **Многоканальность.** В форме v каналов делят слово на части (в дизассемблере —
  массивы состояний 0x529d44/0x529da8 и обнуление при (3,1)+2 каналах). В порте
  код остаётся систематическим, а v задаёт число каналов логической схемы и
  мажоритарное голосование: каждый канал декодирует слово, циклически сдвинутое
  на свой номер, и голосует за разряд. Одиночная ошибка собирает все v голосов
  (проверено для всех кодов и v = 1…5), поэтому порог ⌊v/2⌋+1 достигается.
* **Вердикты.** В форме `BitBtn4Click` сравнивает остаток только с нулём
  («Код принят без ошибок/с ошибкой»). Порт дополнительно сообщает разряд,
  на который указывает синдром, и отдельно — что при кратности > 1 исправление
  неверно (форма этого не различает: остаток ненулевой в обоих случаях).
* **`Label24` «Вектор ошибки».** В форме `Edit3` — именно вектор ошибки:
  принятое слово получается посимвольным сложением с ним (0x50d6c4), а не
  вводится напрямую. Порт делает так же.
* **`BitBtn2Click`** (0x50d6c4) в DFM не виден (скрытая кнопка, `Visible=false`),
  его работу (сложение с вектором ошибки) порт выполняет в «Декодировать».
* **Скрытые кнопки.** `BitBtn3` (0x50c8a8, освобождение списков) и `BitBtn2`
  в интерфейс не перенесены: служебные.
* **Схемы.** `Image1/3/4/5` — растровые рисунки регистра; вместо них таблица
  состояний по тактам, график состояний/синдрома и матрица связей.

## Проверки (`scripts/check_lab8.py`)

* 5 вкладок и их подписи; 5 радиокнопок каналов и 7 многочленов с подписями
  формы; кнопки «Рассчитать остаток», «Декодировать», два «Следующий такт»;
  разрядность полей и линейки номеров.
* g(x): степень r, g(0) = 1, делит x^n+1, n = 2^r − 1, период n (нет делимости
  x^d+1 при d < n) — для всех 7 многочленов.
* d_min = 3 перебором (для k ≤ 12) и выборкой для (31,26).
* Матрица связей M: первый столбец — коэффициенты g, далее единичная; размер
  r×r; F* и степени M^v на вкладке «Описание модели».
* Систематическое кодирование: синдром слова 0, информационная и проверочная
  части, обнуление фильтра после n тактов, длина слова n для всех v.
* Числа примеров: (7,4) A=0111 → R=010, слово 0111010; (15,11) и (31,26) —
  остатки; таблица синдромов (7,4).

  исправленные, исходное слово не выдаётся.

  (7,4) при v = 2 — как в справке.
* Автономный режим: S_t = x^t·S mod g, период n.
* Интерфейс: расчёт остатка, такты кодера (тип разряда «инф./контр./фикт.»),
